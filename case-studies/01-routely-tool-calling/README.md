# Routely — Tool Calling (Case Study 1)

Demo engagement for the LeanInference portfolio: Routely (fake logistics SaaS) sends every
in-app assistant request to a frontier model with all tool schemas in the prompt.
We build an eval set from "real usage", test cheaper alternatives, and prove which one wins.

> Story: "You were using a frontier model for every tool call. We built an eval set from your
> real usage, tested several alternatives, and found a solution with the same (or better)
> accuracy at a fraction of the cost and latency. Here's the proof."

---

## Locked decisions (2026-10-17)

| Decision | Choice |
|---|---|
| Paid API budget | **$0** — no paid API runs. Data generated by the agent (Claude), baseline accuracy **assumed from published benchmarks** (clearly labeled), baseline cost **computed from token counts** × list prices. |
| Frontier baseline (the story) | GPT-6 Astra ($10/$50 per M tokens) — "sends everything to the most expensive tier". Cost reported with and without prompt caching. |
| Candidate A | GPT-6 Luna ($0.10/$0.50), prompt-engineered, all 40 schemas + few-shot. |
| Candidate B | Qwen3.5-4B (spec main) + Qwen3.5-2B (local) + Qwen3.5-0.8B (size-ladder row). QLoRA via Unsloth. |
| Candidate C | Needle 3 (Cactus Compute, Apache-2.0). Locally fine-tuned (LoRA on CPU) — the "even smaller" end of the ladder. |
| Training hardware | Everything **local** (user decision): laptop RTX 3050 6 GB, Unsloth QLoRA. 0.8B/2B comfortably; 4B as a tight-settings attempt. No Kaggle. |
| Eval | 500 hand-verified test examples (frozen, SHA-256); val 200; train 2,432 (3,132 kept from 3,140 generated). |

## Layout

```
01-routely-tool-calling/
  README.md                  <- this file
  requirements.txt
  data/
    tools.json               <- the 40 tools (OpenAI tools format)
    FORMAT.md                <- record format + rules + scoring normalization
    generator/validate.py    <- validator for any batch/split JSONL
    generator/assemble.py    <- dedup + stratified splits + SHA-256 freeze
    generator/apply_review_fixes.py <- review-pass corrections (8 records, documented)
    seed/seed-batch-v1.jsonl <- 45 seed examples (format reference)
    batches/                 <- generation batches land here
    splits/                  <- train.jsonl / val.jsonl / test.jsonl + sha256.txt
    verify/                  <- verification notes + flagged items
  train/
    qwen/                    <- Unsloth QLoRA configs + logs
    needle/                  <- finetune commands + adapter
    experiments.csv          <- every run, ever (the "journey")
  eval/
    run_eval.py              <- model -> results/<model>.jsonl
    score.py                 <- metrics from results + gold
    report.py                <- results table + per-bucket breakdown
    adapters/                <- openai.py vllm.py needle.py (as needed)
    results/                 <- raw per-example outputs (the receipts)
  cost/
    compute_costs.py         <- token counts x list prices -> $/1M + monthly @2M
    prices.json              <- list prices with date stamps
  writeup/
    RESULTS.md               <- final results table (measured vs assumed labeled)
    FAILURES.md              <- 5-10 failure examples from the winner
    CLIENT-ONE-PAGER.md      <- what they used -> what we tested -> recommendation -> savings
```

## Quickstart

```powershell
# validate any batch or split (fetches deps on the fly)
uv run --with jsonschema --with tiktoken python data/generator/validate.py data/seed/seed-batch-v1.jsonl

# eval pipeline smoke test (mock model - no API calls, deterministic, ~1s)
uv run python eval/run_eval.py --adapter mock --model mock-pipeline --seed 42
uv run python eval/score.py --results eval/results/mock-pipeline.jsonl
uv run python eval/report.py

# fine-tune locally (after: powershell -ExecutionPolicy Bypass -File train/qwen/setup_env.ps1)
uv run python train/qwen/prepare_data.py
.venv\Scripts\python.exe train/qwen/train_qlora.py --model Qwen/Qwen3.5-0.8B
```

## Notes

- The demo data is synthetic; no real personal data anywhere.
- Every metric in the write-up must be either **measured** (runs in `eval/results/`) or clearly
  marked **assumed** (baseline accuracy from published benchmarks, with source + date).
- Eval adapters: `mock` (pipeline test — never a result), `openai` (any OpenAI-compatible API — not executed under the $0 rule), `vllm` (local server, `--no-thinking` for Qwen3.5), `needle` (CLI wrapper; command template finalized in the training phase).
- Prices drift — `cost/prices.json` stamps the retrieval date; re-verify before publishing.
