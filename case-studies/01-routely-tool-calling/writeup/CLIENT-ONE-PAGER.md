# Routely: stop paying frontier prices to pick one of 40 tools

*LeanInference case study 1. Every number comes from a run on our 500-example, hand-verified test set
(`writeup/RESULTS.md`, regenerated by `python eval/final_table.py`). Volume: 2,000,000 calls/month.*

## What you have today

Every assistant request goes to a frontier model (GPT-6 Astra, $10 / $50 per million input / output
tokens) with **all 40 tool schemas in the prompt - 5,304 tokens per call** before the user has typed a
word. That is **about $116,000 a month**, and 97% of the prompt (5,141 tokens) is the same schemas re-read on every call.

## What we tested (same 500 requests for every model)

| Model | Overall correct (before → after) | Right tool | Args exact | No-tool / clarify | p95 | Monthly $ | Runs where |
|---|---|---|---|---|---|---|---|
| Baseline proxy: gpt-oss-120b, all schemas | *pending (71/500)* ¹ | | | | | | API |
| A: MiniMax M3.1 Flash, all schemas | 83.6% | 98.6% | 82.2% | 97.5% | 5.0 s | $3,005 | API |
| B1: Qwen3.5-0.8B fine-tuned, **no schemas** | 7.6% → 78.8% | 95.7% | 78.7% | 97.5% | 5.5 s ² | $1,292 | your cloud (GPU) |
| **B2: Qwen3.5-2B fine-tuned, no schemas** | 15.8% → **82.0%** | **97.9%** | 81.3% | 94.9% | 5.1 s ² | **$1,292** | **your cloud (GPU)** |
| C: Needle 3 fine-tuned (63 MB, on-device) | 2.0% → 43.2% | 59.4% | 59.6% | 84.8% | 0.8 s (CPU) | $130 | your cloud / device |

"Overall correct" is strict: right tool, every argument exactly right (including free-text
`reason` fields), or the right clarify / no-tool decision. ¹ Candidate A remains the provisional bar
while the gpt-oss-120b baseline is incomplete. ² Measured on a 6 GB laptop GPU in
4-bit; self-hosted cost = 3 rented L4 GPUs sized from that latency, so it is conservative.

## What we found

1. **A fine-tuned model doesn't need the schemas.** Fine-tuning taught Qwen3.5-2B the 40 tools: with a
   278-token prompt instead of 5,304 tokens it picks the right tool 97.9% of the time and is correct
   overall on 82.0% - within 1.6 points of the hosted model that reads all the schemas, and better than
   it on look-alike tools (68.8% vs 62.3%).
2. **Most remaining "errors" are wording, not actions.** 50 of the 2B model's 90 misses differ only in a
   free-text `reason` ("no longer needed" vs "shipment no longer needed"). Scored on the action alone the
   2B model reaches 92.0% (Candidate A 95.8%).
3. **Dates are the real gap.** "This Friday", "the 18th": 78% for the 2B model vs 96% for Candidate A.
   Resolving relative dates in code (the rules are already written down) removes that gap without a
   bigger model.
4. **Needle 3 is not ready for 40 tools.** It improved 20× with fine-tuning but tops out at 43%.

## What we recommend

- **Today, by the brief's rule (cheapest that meets the bar): Candidate A** - the same full-schema
  prompt on a mini-class model, **$116,080 → $3,005 a month (-97%)**. It is still a third-party API.
- **Recommended next step: Qwen3.5-2B fine-tuned, self-hosted, plus a deterministic date resolver** -
  **$1,292 a month (-99%)**, no schemas in the prompt, no third party, no frontier fallback. On the
  strict metric it sits 1.6 points under A; if the frontier baseline proxy lands at or below 82.0%, it
  is the winner outright under the brief's rule.

## How the numbers were produced

3,140 generated requests (40 tools incl. confusable pairs, relative dates, multilingual, clarify,
no-tool), 2,432 train / 200 val / 500 test; the test set is frozen (SHA-256) and was hand-verified in
two passes. Training scripts in `train/`, evaluation in `eval/`; every run - including the 4 failed
Qwen attempts that carried all schemas in the prompt (2 out of GPU memory, 2 Windows/library errors), and Needle's first run (18.6%, a
train/inference format mismatch we found and fixed) - is in `train/experiments.csv`.
